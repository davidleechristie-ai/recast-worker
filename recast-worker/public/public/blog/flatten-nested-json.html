How to Flatten Nested JSON

Nested JSON is natural for APIs and applications, but many downstream tools expect flat rows and columns. Flattening converts nested object paths into simple keys so the data becomes easier to inspect, export to CSV or map into systems that do not understand nested structures.

Flatten now: use Flatten JSON in your browser.

What flattening actually changes

A nested object such as {"customer":{"name":"Ada"}} can become a flat key such as customer.name. The value stays the same; only the representation of the path changes. This makes the relationship explicit without keeping the nested object structure.

Why flatten before CSV export

CSV is tabular. Deep JSON objects are not. Flattening gives nested values stable column names, which makes a later JSON to CSV conversion more predictable. This is especially useful for API responses that contain nested customer, address or metadata objects.

Arrays need a deliberate strategy

Arrays are harder because a single row can contain zero, one or many child records. Depending on the goal, you may preserve the array as a value, expand indexes into paths, or create multiple rows. There is no universally correct choice, so decide based on the downstream format.

Do not flatten away useful meaning

Flat data is convenient, but nesting carries context. If your application consumes JSON directly, flattening everything can make the model harder to understand. Use flattening when the next step benefits from it—tabular export, field mapping, spreadsheet work or simple key-value processing.

Unflatten when you need the hierarchy back

If you have flat path-based data and need to reconstruct the original structure, use Unflatten JSON. Round-tripping is most reliable when key-path conventions are consistent and arrays have been handled deliberately.

A common API workflow

A practical sequence is: receive an API response, flatten nested objects, select the fields you actually need, then export to CSV. If you repeat that sequence, Recast can turn the steps into a reusable workflow rather than making you rebuild the transformation each time.
