Transform messy data

Converting a format is one thing — but sometimes you don't just want different formatting, you want a different, cleaner version of what you already have: fewer fields, renamed fields, or a new field built out of two others. That's Transform Builder — click "Transform Builder" above the input box to open it.

It works by chaining simple steps — select, remove, rename, filter, combine, convert type — each with a live preview, and each step correctly sees the output of the step before it (not the original data), so a field you renamed in step 1 is what step 2 actually works with.

Before
{ "first": "John", "last": "Smith" }
After — 3 clicked steps
{ "first_name": "John", "last_name": "Smith", "full_name": "John Smith" }

Rename first → first_name, rename last → last_name, then combine {first_name} {last_name} into a new full_name field — no code, three clicks, live preview after each one.

Try it: Open Transform Builder, or click "Transform Builder" from any data already in the input box.

For developers

Transform Builder is a pipeline of steps — each step's output becomes the next step's input, so a field renamed in an earlier step is what a later step actually operates on. Renaming a nested field can leave its now-empty parent container behind, which is why a real chain often includes a cleanup remove step before flattening. Saving the whole chain as a Recipe stores exactly this step list — the same format the API and CLI run.

[
  {
    "op": "select",
    "params": {
      "paths": [
        "name",
        "address.city"
      ]
    }
  },
  {
    "op": "rename",
    "params": {
      "from": "name",
      "to": "customer_name"
    }
  },
  {
    "op": "rename",
    "params": {
      "from": "address.city",
      "to": "city"
    }
  },
  {
    "op": "remove",
    "params": {
      "paths": ["address"]
    }
  },
  { "op": "flatten" }
]

Result: { "customer_name": "Sarah", "city": "London" }
