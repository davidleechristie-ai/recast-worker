1. Automation

Anything you find yourself doing more than once is worth saving instead of repeating. Build a workflow once by clicking through it — reshaping, filtering, converting, checking — then save it as a named, reusable sequence. From there, the exact same sequence can be re-run in one click, called from a script through the API, or run from the command line. You build it visually once; where it runs after that is up to you.

A few examples of what that looks like in practice — built from the real steps above, chained for a specific job:

Daily sales

Get data → Clean → Convert → Output

API monitoring

Get API response → Validate → Compare → Output

Incoming files

Receive file → Transform → Validate → Output

These are patterns, not pre-built templates — Recast doesn't ship a "daily sales" workflow out of the box. Each one is built from the same real steps (Select, Filter, Rename, Convert, Validate, Compare) chained together in Recipe Builder for your specific data.

If you perform the same steps repeatedly, save your workflow and run it again.

A recipe is a named, ordered list of steps you can re-run without rebuilding it — this is live, working functionality today, not a preview. There are two ways to build one:

  • The Recipe panel — the simpler, original version. Add steps, save, run.
  • Recipe Builder 2.0 — a full visual Input → Output workflow. Steps run down the page as connected cards; drag to reorder them; click any step to preview the result at that point, not just the final output; edit a step's settings without rebuilding the whole chain. Field pickers throughout stay aware of what earlier steps already did — rename a field in step 1 and step 3's dropdown correctly offers the new name, not the old one.

Once saved, either kind of recipe can be run again from the API or the CLI — a workflow you built by clicking becomes something a script can call automatically.

Try it: Open Recipe Builder 2.0, or load the real orders demo to see it pre-loaded.

3. Batch processing

One file is easy. 100 files shouldn't mean 100 separate jobs.

One pass, one result per file

The Batch button (next to Upload) lets you drop in multiple files and run the same conversion, validation, or diff across all of them in one pass, instead of pasting them in one at a time. Most conversion, validation, and diff modes support it.

Batch conversion is a Pro feature, currently supporting up to 100 files at once per batch.

⚡ Pro feature — up to 100 files

Try it: Open the tool and click "Batch."

4. API / CLI

This part is genuinely optional — most people never need it. It's for one specific situation: you want your own software to do this automatically, without a person copying and pasting each time.

Two ways to get there, both currently live:

  • REST API — send the same conversions, transforms, validations, and diffs over HTTP, from any backend, script, or internal tool. Saved recipes can be called the same way.
  • recast-cli — an npm package running the identical engine locally, no network dependency at all.
If none of that meant much to you, that's fine — it means you don't need it. Everything above (recipes, batch, the visual builder) covers the vast majority of what people actually use Recast's automation tools for.

Exact request formats, authentication, and code examples in several languages live in the full API documentation on the main tool page.

Try it: Open the API Workbench.

Common questions

What counts as something worth automating?

Anything you find yourself doing more than once — reshaping, filtering, converting, or checking the same kind of data repeatedly.

How do I build an automated workflow?

Build it once by clicking through the steps — reshaping, filtering, converting, checking — then save it as a named, reusable sequence.

Can I run a saved workflow outside the browser?

Yes — the same saved sequence can be re-run via recast-cli or the API, not just in the browser.
