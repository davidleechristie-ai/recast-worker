Compare data

Diff takes two versions of the same file and highlights exactly what changed, like tracked changes in a document. For JSON specifically, Structural Analysis goes further — it doesn't just say something changed, it tells you whether that change is actually safe.

Before
[ { "id": 1, "name": "John" }, { "id": 2 } ]
After
[ { "id": 1 }, { "id": 2 } ]

The name field disappeared from record 1 — but it was only ever present on some records to start with, so Structural Analysis correctly calls this Uncertain, not Breaking. If a field had been on every single record before disappearing, that's when it's confidently flagged as Breaking. It's deliberately cautious: never guesses when the evidence isn't there.

Try it: Open Compare, then click "Structural Analysis" once you've run a JSON diff — or load the real orders demo to see a genuine before/after pair.

Find out what changed

You have yesterday's data and today's data. They look almost identical. Recast tells you exactly what changed.

Yesterday 
{
  "name": "Sarah",
  "email": "sarah@example.com"
}
Today 
{
  "name": "Sarah",
  "email": "sarah@example.com",
  "phone": "0123456789"
}

+ Added phone — the one thing that's genuinely different between the two.

A real comparison usually involves more than just additions. Here's the same idea with a few more changes at once:

= Unchangedname"Sarah"
~ Changedemail"sarah@example.com" → "sarah@work.com"
− Removedcitywas "London"
+ Addedphone"0123456789"
Developers often call this a diff.

Compare CSV files

The same idea works for spreadsheets, not just JSON — and it's genuinely row-aware: if you reorder or delete a row, Recast still matches it up correctly by its actual content, instead of comparing by line position and reporting dozens of false changes.

Common questions

What's the difference between Diff and Structural Analysis?

Diff highlights exactly what changed between two versions of a file. For JSON specifically, Structural Analysis goes further and tells you whether a change is actually safe or potentially breaking.

Can it tell the difference between a real breaking change and a harmless one?

Yes — for example, if a field was only ever present on some records to begin with, its absence elsewhere isn't flagged as a breaking change.

Which formats can I compare?

JSON, CSV, and XML.
