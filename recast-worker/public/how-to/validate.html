Check whether your data follows the rules

A schema is simply a set of rules describing what your data should look like.

name    = text
age     = number
active  = true/false
Developers often use JSON Schema to describe these rules.

Validate checks your file for real errors — a missing comma or bracket — and tells you exactly where the problem is, for both JSON and XML, instead of a browser's cryptic parser error.

Schema does the opposite job: instead of checking against rules, it looks at a real sample of your data and generates the rules — a JSON Schema describing which fields exist, their types, and which are required. Once you have that schema, Validate against Schema checks real data against it.

Recast checks whether the data follows the rules and shows you what needs fixing. Say your rules expect these three types:

Expected 
name     → string
age      → number
active   → boolean
Actual 
name     → string       ✓
age      → "thirty"     ✕
active   → boolean      ✓

One field doesn't match — age came through as text instead of a number. In plain English, before anything technical:

✕ Problemageshould be a number, but it's text
For developers

The same check reported in JSON Schema terms — this is the real, unmodified output of validateAgainstSchema:

{
  "valid": false,
  "errors": [
    {
      "path": "age",
      "message":
      "expected type integer, got string"
    }
  ]
}

Useful for describing your data's shape to another system, or as a check in a CI pipeline that catches breaking API changes before they ship.
