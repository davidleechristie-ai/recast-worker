Example: detect an API contract change

Suppose one response returns "customer_id": 42 and a later version returns "customerId": 42. A structural comparison identifies the removed and added paths directly. It can also expose type changes such as a number becoming a string.

Before: {"customer_id":42,"status":"active"}
After:  {"customerId":42,"status":"active","tier":"pro"}

The meaningful changes are the renamed identifier and the new tier field—not line positions or whitespace.

Compare API response questions

How do I compare two API responses?

Capture the two JSON payloads and compare them structurally. Review changed JSON paths rather than only line-level differences.

Can I ignore formatting differences?

Yes. Structural comparison parses the JSON first, so indentation, whitespace and key formatting do not create false data changes.

What about reordered arrays?

Where records have stable ID-like fields, identity-aware matching can reduce reorder noise. Keep order significant when the API semantics depend on sequence.
