How to Compare Two JSON Files

Comparing JSON as plain text is easy to start and often frustrating to finish. Whitespace, property order and reordered arrays can make a text diff look much larger than the underlying data change. For configuration, API responses and fixtures, structural comparison is usually more useful.

Compare now: open JSON Diff to compare two JSON documents in your browser.

Text diff versus structural JSON diff

A text diff compares lines and characters. A structural JSON diff parses both documents first and compares keys, values, objects and arrays. That means formatting changes do not become fake data changes, and nested paths can identify where the real difference occurred.

Focus on added, removed and changed values

A useful comparison should answer three questions: what was added, what disappeared, and what changed. For nested data, paths such as customer.address.city are much easier to act on than a highlighted line with no structural context.

Array order can create noise

Suppose two API responses contain the same customer records but return them in a different order. A position-based comparison can report many changes even though no customer changed. When records contain stable identifiers, matching array items by an ID-like key can isolate genuine changes.

For that use case, Recast also has a focused Compare JSON Arrays by ID page.

Check semantics before ignoring order

Not every array is a set of records. In some APIs, order is meaningful: ranked search results, transaction sequences and workflow steps are examples. Only ignore or key-match order when the domain says the records are identifiable independently of their position.

Compare API responses before and after a change

JSON diff is particularly useful during API migrations and refactors. Capture a representative response before the change, run the same scenario afterward, then inspect the structural differences. This is a quick way to catch renamed fields, type changes, missing properties and unexpected additions.

Validate after you compare

A diff tells you what changed; a schema validator tells you whether the new shape is still allowed. For contract-sensitive workflows, combine comparison with JSON Schema validation.

Keep comparison private when the data is sensitive

For local browser tools, Recast processes the working data in the browser. That makes it suitable for many development payloads where uploading internal responses to a third-party comparison service would be undesirable. Hosted API and Automation features are separate and only apply when explicitly used.
