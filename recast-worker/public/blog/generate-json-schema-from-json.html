How to Generate JSON Schema from JSON

If you already have a representative JSON payload, writing its schema from scratch is usually unnecessary. A faster approach is to infer a starting schema from the sample, inspect the generated types and required fields, then tighten the contract where your application needs stronger rules.

Need the tool now? Use the JSON Schema Generator to paste JSON and generate a schema in your browser.

What a JSON Schema generator does

A generator looks at the structure of your sample JSON and turns observations into schema rules. Strings become string, numbers become numeric types, objects become nested properties, and arrays are represented with an items schema. The result is a machine-readable description of the payload shape.

{
  "id": 42,
  "name": "Ada",
  "active": true
}

A generated schema can infer that id is numeric, name is a string and active is boolean. It can also describe nested objects and arrays that would be tedious to model manually.

Generation is a starting point, not an oracle

Inference only knows what appears in the sample. If one example contains a field, the generator cannot know whether that field is genuinely required for every future payload. Likewise, a sample string does not reveal whether the real domain is an email address, UUID, date-time or a fixed set of values. Treat generated output as an accurate structural baseline, then apply domain rules deliberately.

Use representative JSON

The best sample includes the kinds of values your application actually receives: optional-looking fields, nested collections, empty values and realistic arrays. If you generate from an unusually small or clean example, the schema can become stricter than the real API or looser than the contract you intend.

Review arrays carefully

Arrays are a common source of misleading inference. A single-item array gives only one example of the item shape. If later elements can vary, confirm whether the schema should permit that variation. For APIs, it is often worth generating from a response that includes several representative records.

Add constraints after the shape is right

Once the structure is correct, refine it with rules such as minimum and maximum values, allowed values, string formats and patterns. This is where a generic generated schema becomes an application contract rather than merely a description of one example.

Validate real data against the result

The value of a schema appears when you use it. Take the generated schema and validate current or future payloads against it. Recast provides a dedicated JSON Schema Validator for that step. It is useful for checking API responses, configuration files, fixtures and data exchanged between services.

Generation and validation solve different problems

The generator answers “what does this sample look like?” The validator answers “does this payload conform to the contract?” Keeping those tasks separate makes the workflow clearer: generate once, review the contract, then validate repeatedly.

When this works especially well

Schema generation is useful when documenting an existing API, introducing contract tests around legacy integrations, creating a baseline before refactoring, or converting an informal payload into something that CI can enforce. If the payload is changing rapidly, regenerate from representative samples and compare the contract changes before adopting them.
