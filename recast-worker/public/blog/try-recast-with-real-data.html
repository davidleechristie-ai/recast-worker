Stop making up test data — try Recast with the real thing

Evaluating a data tool usually comes down to two bad options. Either you paste in something of your own — which means handing a piece of your actual data, maybe customer records or business numbers, to a website you've never used before — or you type out three fake rows just to see the tool do something, which tells you almost nothing about how it behaves once the file is real.

A three-row example can't show you what happens when a CSV export has a column that's missing from half the rows. It can't show you whether a diff tool actually holds up once you're comparing hundreds of records instead of three. So we built a page specifically to skip both problems.

What's actually on the demo page

Not placeholder text — real, generated datasets, sized like something you'd actually export from a real system:

  • 2,500 e-commerce orders (JSON, 1.4 MB) — nested customer info, shipping addresses, and line-item arrays. This is the shape that breaks naive flatteners.
  • 4,000 employee records (CSV, 408 KB) — flat, typed columns: salary as a number, remote status as a boolean, straight through automatic type inference.
  • 2,500 service log events (XML, 646 KB) — timestamped entries across 8 services, the kind of export an ops team would actually pull.
  • 150 microservice configs (YAML, 52 KB) — replicas, resource limits, environment variables, autoscaling rules.
  • A real before/after pair for the diff tool — 400 orders, then the same set a day later: statuses progressed, a handful cancelled, a few refunded away entirely, some brand-new ones added.

The diff pair is the one worth trying first

Diff tools are hard to evaluate from a tiny example, because a 5-row diff barely tests anything. The demo's order pair is sized to actually show what key-aware diffing is for: run it, and you'll see 225 real changes — 188 status or total changes, 12 orders removed, 25 added — each one matched correctly by order ID rather than by row position, so a removed order in the middle of the list doesn't cascade into false-positive changes on every row after it.

Two ways to load it

Tap any card to load it straight into the converter and jump you there — works everywhere, including on a phone. On desktop, you can also drag a card directly onto the input panel, or onto the API playground further down the page, and drop it there — the same drop-zone the file-upload feature already uses, so it behaves exactly like dropping a file from your own computer would.

Go try it — the demo page is here. Nothing to prepare, nothing of your own required, and like everything else in the browser tool, none of it is uploaded anywhere.
